# Contributing to Awesome Server-Side Tracking

Thank you for helping curate tools and technical resources for reliable, privacy-aware server-side measurement. By participating, you agree to abide by the [Code of Conduct](CODE_OF_CONDUCT.md).

## Submission Guidelines

- **Relevance:** Submit resources that help practitioners build, operate, or understand server-side tracking and measurement. Tools, open-source projects, official documentation, specifications, technical guides, and communities are welcome.
- **Active maintenance:** Tools and projects should be actively maintained. Documentation and other reference resources should be current and useful.
- **Direct, working links:** Link directly to the resource, not to a search engine or redirect service. Affiliate, tracking, and referral links are not allowed.
- **No duplicates:** Search `README.md` before adding a resource.
- **Public access:** Resources should be publicly accessible. Prefer official documentation and open-source projects over promotional landing pages.

## Description Standards

Write a short, objective description of the resource's purpose and core features. Avoid pricing, promotional claims, superlatives, and marketing language.

- **Do:** “Receive, process, and export telemetry through configurable pipelines.”
- **Don't:** “The world's best platform that revolutionizes your tracking.”

## Step-by-Step Submission Process

1. **Star the repository:** If you find it useful, consider starring it to show your support.
2. **Locate the file:** Open `README.md` and click the **Edit** (pencil) icon, or edit it in your local checkout.
3. **Add your resource:** Choose the most relevant category and use the existing Markdown format. Use the `github` icon when the primary link points to a GitHub repository and the `web` icon otherwise. Link directly to the resource:
   ```markdown
   ![github](image/alg_R.png) [Resource Name](https://github.com/org/repo) - Short, objective description of what it does.

   ![web](image/alg_I.png) [Resource Name](https://example.com) - Short, objective description of what it does.
   ```
4. **Check your changes:** Follow the [checks below](#checks) before submitting.
5. **Create a pull request:** Use a clear title such as `Add [Resource Name]`.

## Checks

There are currently no automated checks configured in this repository. Before opening a pull request, please check that:

- The link works, is publicly accessible, and points directly to the resource without tracking or referral parameters.
- The resource is relevant, current, and not already listed.
- The entry is in the appropriate category and follows the existing list format.
- The description is concise and factual, without pricing or promotional claims.
- The Markdown renders correctly and the diff contains only the intended changes.
